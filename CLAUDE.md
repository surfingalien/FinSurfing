# CLAUDE.md

Guide Claude Code (claude.ai/code) for this repo.

## Commands
`npm run dev` — Vite:5173 + Express:3001 concurrently | `npm run build` → dist/ | `node server.js` — prod only | `npm test` — Jest unit tests in `tests/` (also run by CI on every PR). No lint.

## Stack
React18+Vite SPA → Express API proxy. Dev: Vite proxies `/api/*` → :3001. Prod: single process :3001 serves dist/+API.

**Learning stores survive deploys via `lib/durable-files.js`.** Every Brain store (predictions, learning-store, strategy-library, brain-learnings(+overrides), ml-baseline-weights, rec-journal, entity-graph, paper book, brain-refinements, scan-jobs) is a file under `data/`, and Railway's disk is wiped on every deploy — before this, deploys 8–28 days apart meant no 30d outcome could ever resolve. The files are MIRRORED to Postgres table `durable_files` (gzipped, versioned): `restoreSync()` runs at the very top of `server.js`, in a child process, BEFORE any route/lib is required (`ai-job-queue` reads at require time) and the DB copy wins; `startMirror()` pushes changed files every 30s; `installShutdownFlush()` does a last push on SIGTERM. **A failed restore disables flushing for the whole process** — the disk then holds the git seed, and flushing it would overwrite the real history. Writes are version-conditional; on conflict the running process adopts the newer version and wins next tick. **Adding a new `data/` store? Register it in `FILES`**, or it resets every deploy. Status: `persistence` on `GET /api/evolution/status`. Inert without `DATABASE_URL` or with `DURABLE_FILES=off`. Tests: `tests/durable-files.test.js`.
**DB**: `DATABASE_URL` → Postgres; missing → memstore. Schema: `db/schema.sql`. Set `DATABASE_CA_CERT` (PEM, literal or `\n`-escaped newlines) to pin the Postgres TLS cert chain (`rejectUnauthorized: true`); unset in production → encrypted-but-unverified TLS + startup warning.
**Client state**: localStorage: watchlist, alerts, AI watchlist, `finsurf_api_keys`. Portfolio → DB when authed.

## Long AI requests: queue vs heartbeat
A long request that writes no bytes gets dropped by mobile networks, and the browser reports that as a bare **"Load failed"** — a fetch rejection with no HTTP response at all. Two mechanisms, picked per surface:

**Background queue** — `POST` enqueues, the run happens server-side, the result is persisted and outlives the tab. For expensive, explicitly user-triggered, one-at-a-time runs where losing the result wastes a paid LLM call: **AI Brain scan**, **Advisory recommendations** and **Exposure Map builds**. Server side, `lib/ai-job-routes.js:mountJobRoutes(router, { kind, requireAuth, buildParams, ... })` mounts all five endpoints (`POST <base>`, `GET <base>/latest`, `GET <base>/:id`, `DELETE <base>/:id`, `GET <listPath>`) with the ordering, owner-scoping, kind-filtering and rate-limit skip already right; it also stamps `params.userId` so a queued run keeps its owner (read back with `middleware/auth.js:effectiveUserId`, which honours a body `userId` ONLY for a verified `isInternalRequest()`). Client side, `src/hooks/useBackgroundJob.js` owns enqueue + poll + resume-on-mount. Adding a surface = one `JOB_KINDS` entry + one `mountJobRoutes` call + one hook call. Tests: `tests/ai-job-queue.test.js`, `tests/ai-job-routes.test.js`.

**Heartbeat** (`lib/http-heartbeat.js`) — trickles a space every 15s so the connection never idles. For long requests the queue would make *worse*: auto-triggered or per-symbol surfaces (a queue would hit the per-user cap while browsing and restore the wrong symbol's result), and anonymous ones (job ownership needs a user). Applied to `trading-analysis/analyze`, `dividend/screen`, `dcf`, `patterns/:symbol`, `strategy-lab/propose`. **Once heartbeating starts the status pins to 200, so clients MUST check `data.error` as well as `res.ok`.**

**Neither** — SSE surfaces (`copilot`, `agent/analyze`, `rebalancer/suggest`) already stream bytes continuously; do not add a heartbeat to them, it corrupts the event stream and overwrites the `text/event-stream` content type.

## FMP client (`lib/fmp.js`)
**Every FMP call goes through `lib/fmp.js` — never build an `api/v3` URL in a route.** FMP refuses `/api/v3` + `/api/v4` for keys issued after 31 Aug 2025 ("Legacy Endpoint", often HTTP 200), and every call in the repo was v3, so on a current key fundamentals, screener, DCF, dividends, fund NAVs, earnings and news were all dead while the quote cascade silently moved on. Each function tries the **stable** API first, legacy second, and returns the **legacy response shape**; the `*ToLegacy` adapters ADD old field names (`changesPercentage`, `mktCap`, `lastDiv`, `peRatioTTM`, `roeTTM`, `calendarYear`…) without dropping new ones. `metricsTtm` merges key-metrics-ttm + ratios-ttm (stable split them). In-body refusals throw `FmpError` with FMP's message; when both paths fail the STABLE error is reported. `insiderSide()` classifies Form 4 rows by SEC code (P buy, S sell, A/M/F/G `other`) — the old substring test read "S-Sale" as a buy. The provider health probe and the Research Desk "Is it working?" FMP check make a live call, because "key set" ≠ "key works". Institutional holders / short interest / options have no stable equivalent on most plans and stay legacy. Tests: `tests/fmp.test.js`. (Sandbox note: Node's `fetch` ignores `HTTPS_PROXY` unless `NODE_USE_ENV_PROXY=1`.)

## Live prices, fresh lists, and levels on every card
**Live-price gate** (`routes/ai-brain.js`). Every symbol the model analyses must carry a REAL price — the live quote, else the last daily close from the bars (≤5 days old). The prompt used to say "no live data — use training knowledge", letting the model price stocks from memory. Now unpriced symbols are removed from the scan and listed (`unpricedSymbols`); a pick for a symbol outside the priced universe is dropped; each card's `currentPrice` is overwritten with the real price (`priceSource`, `priceAsOf`); and a scan with no price for anything is refused with an error rather than run. `dataAge` is `live` or `mixed`.

**Discovery universes** (`lib/scan-universe.js`). `broad`, `stocks`, and every stock-sector mode (incl. legacy `tech`/`finance`/`healthcare`/`energy`) build a NEW list each scan: today's most-active + biggest-gaining US stocks (`getMovers`, FMP `stable/most-actives`/`biggest-gainers` with v3 fallback, 10-min cache, filtered to the sector via `symbol-db.classify`), up to 5 curated names, then a rotating draw from the sector's large caps — the LIVE pool first (`getLivePool`: one FMP `stable/company-screener` / v3 `stock-screener` call per sector, most-traded first, 1h cache, `FMP_SECTORS` maps GICS→FMP names), `symbol-db.sectorUniverse` only as a fallback, because the local index is downloaded after boot and may not be loaded (a scan built on the index alone re-used the same 20 core names every time). Movers are sector-matched by the index OR by membership in the live sector pool. Names the previous scan of the mode covered go to the back (`_recentByMode`, in-memory); `broad` always keeps `BROAD_FIXED` (SPY/QQQ/BTC/ETH). Each pick carries `universeSource` (mover/core/pool/fixed); the response carries `universeSources` + `universeRequested`. `universeMode:'curated'` restores the fixed lists; ETF/crypto/fund modes stay curated. `SCAN_PROMPT_VERSION` 4.

**Trade plan on every card** (`lib/trade-levels.js`). `tradeLevels()` returns entry range, stop range and two profit-booking levels (T1 book partial, T2 target) with R-multiples. THESIS mode (actionable pick): levels from its targetReturn/stopLoss and entry, T1 halfway to target. TECHNICAL mode (declined pick / Research Desk no-trade / pre-thesis dossier): from the bars alone — entry near support within one ATR, stop below both, booking at 1.5R and 3R — labelled "reference levels, not a buy signal" and never logged as a prediction. A stop inside one ATR is flagged. Attached as `tradePlan` on every AI Brain pick, as `judgement.tradePlan` on every Research Desk thesis, and as `referenceLevels` on the evidence dossier. UI: `TradePlan` in `AIBrain/scan/StockCardParts.jsx` (reused by the Research Desk); `ScanAgeBanner` warns when a restored scan is ≥12h old. Tests: `tests/trade-levels.test.js`, `tests/scan-universe.test.js`, `tests/ai-brain-abstain.test.js`.

**"Is it working?"** (`GET /api/research-desk/system-status`, `lib/system-status.js`, Research Desk tab). Each part of the pipeline checked live and reported ok/warn/fail with the reason and the fix: market data (one SPY probe quote, bars fallback), AI provider keys / Claude pause, FRED, FMP, persistence, symbol index, the user's latest scan and its age, the scheduled jobs that keep the record honest (last run/error since this boot), and the prediction record (logged / scored / next outcome due). Never calls an LLM. Tests: `tests/system-status.test.js`.

## AI Brain Self-Improvement (`lib/brain-learnings.js`)
Nightly loop: `resolveOutcomes()` resolves predictions logged 7d/30d ago against the historical daily bar at exactly +7/+30d (not run-time price), records entry-zone fill (`entered`) and benchmark return (SPY equities / BTC crypto) → writes back to `data/ai-brain-predictions.jsonl`.

**Triple-barrier label** (`tripleBarrier()`, stored as `barrier` on each record, computed once the 30d window has fully elapsed). The fixed-horizon return answers a question nobody asked: a pick that hit its target on day 3 and round-tripped scores as a loss, one that blew through its stop on day 2 and recovered scores as a win. `tripleBarrier()` walks the daily bars and reports which level price touched FIRST — `target` / `stop` / `time`. **The record's `stopLoss` is a PERCENT; `barrierLevels()` converts it (and `targetReturn`) to PRICES from the entry anchor, preferring the logged `stopZoneMid`** — the resolver once passed the percent straight in, so a $100 stock with an 8% stop was checked against $8 and a 40% crash scored as `time`. `barrierV` versions the label so pre-fix labels recompute. **Both barriers inside one daily bar resolves as the stop** (intraday order is unknowable from daily data, and assuming the win inflates every rate in the direction that flatters the system); no bars covering the window returns `null`, never `'time'` — a data gap is not a measured non-event. It is a SECOND label, not a replacement: the fixed-horizon return stays, because alpha vs a benchmark is also held for a fixed horizon. Surfaced as `stats.barriers` (targetFirst / stopFirst / neither / avgDaysTo*), which measures whether the stated targets and stops were REACHABLE. **Deliberately not an `edge-report.js` dimension** — the label is an outcome, so segmenting returns by it is circular.

**Scan-context stamping.** Every prediction carries `regimeAtScan` (the FRED regime string already injected into that scan's prompt — the same one the model reasoned from, not a re-derivation), plus `modelVersion` + `promptVersion` (`routes/ai-brain.js:SCAN_PROMPT_VERSION`, **bump it whenever the scan prompt changes in a way that could move the picks**) and `stopLoss`. `computeStats()` derives `byRegime` and `byModelVersion` (keyed `model/vN` — either changing makes a new system, and pooling them yields a number describing neither); both are `edge-report.js` dimensions. Records predating a stamp are EXCLUDED, never bucketed as `unknown`, which would read as a real segment with a real hit rate. `computeStats()` derives win rates, alpha win rates, target-hit rates and per-confidence calibration deterministically in code.

**Statistical hygiene (`lib/calibration-stats.js`).** (1) **One horizon per stats run**: every segment used to take a record's 30d return when resolved and its 7d otherwise, pooling two questions; now `segmentHorizon` is 30 once `SEGMENT_MIN_30D` (20) thirty-day outcomes exist, else 7, and records lacking it are excluded. (2) **Every rate carries a 95% Wilson interval** (`winRateLo/Hi`, `alphaWinRateLo/Hi`) plus exact counts (`wins`, `nBench`, `alphaWins`); the alpha denominator is `nBench`, not `n`. (3) **The composite-score cutoff is walk-forward validated** (`validateThreshold`): chosen on the older 70%, adopted only if its holdout Wilson lower bound beats the unfiltered holdout rate. The old in-sample grid search reported ~61% on 50% coin-flip data and was applied as a LIVE filter; `getAutoTunedThreshold()` also fell back to the LLM's `bestCompositeThreshold` — removed: **no validated cutoff ⇒ no filter**. `stats.autoTune.reason` says why. (4) `lib/edge-report.js` tests each segment against the same-horizon overall rate and applies **Benjamini–Hochberg (FDR 10%) across every segment tested** — only survivors are `topEdges`/`topDrags`; `edgeBlock` says "NO MEASURED EDGE" rather than listing the luckiest. (5) `kelly.winProbFromStats` **shrinks** the measured rate toward the fallback (`shrinkRate`, 20 pseudo-observations) — Kelly is steep in p, and a raw 70% off 20 picks sizes as 60%; `raw` is returned alongside. Tests: `tests/calibration-stats.test.js`. `runMetaAnalysis()` has Claude interpret (not compute) those stats and write structured learnings to `data/brain-learnings.json`. `getLearningsBlock()` returns a prompt-injection string injected into the AI Brain system prompt. Reads from disk JSONL only — no user input reaches the file path. **`data/ai-brain-predictions.jsonl` is the real calibration record and is NOT in git** (gitignored; persisted via `lib/durable-files.js`). It used to be tracked — and the only rows ever committed were six fake AVAX picks a route test wrote, which would have been resolved against real bars and counted as measured evidence. Anything exercising `POST /analyze` appends to it. `AI_BRAIN_PREDICTION_LOG` overrides the path (server-operator controlled, never user input); **any test touching that route must set it before requiring the route**, since the path is read once at module load. `tests/ai-brain-abstain.test.js` pins that the redirect is honoured rather than assuming it. `lib/ml-baseline.js`: transparent logistic TA model logged per pick (`baselineDir/Prob/Features`) as a mechanical benchmark; `computeStats()` reports AI-vs-baseline; nightly cycle refits weights (≥100 resolved rows) → `data/ml-baseline-weights.json`.

**Walk-forward promotion gate.** The nightly refit runs unattended and whatever it saves becomes the benchmark every future scan is scored against, so "refit succeeded" ≠ "refit is better". `trainFromRecords()` holds out the NEWEST 25% by time (`splitByTime` — never a random split; shuffling would train on next month to predict last month), fits a candidate on the older rows, then scores candidate / incumbent / majority-class base rate on the untouched holdout (`evaluateWeights` → accuracy + logLoss + baseRate). It ships **only if the candidate beats both** the base rate and the incumbent; otherwise the incumbent stands and `reason` says why. On promotion it refits on ALL rows before saving (the holdout proved the procedure; the shipped model shouldn't lose the most recent evidence) and carries `validation` provenance on the weights file. Returns `{trained, promoted, rows, validation, reason}` — `trained` stays true for a fit that ran and was rejected, so "no data yet" and "rejected" are distinguishable in the job log. Tests: `tests/ml-baseline-walkforward.test.js`.

## AI Brain Evolution (`lib/brain-evolution.js` + `lib/strategy-library.js` + `lib/learning-store.js` + `lib/paper-broker.js`)
Turns the Brain from "tunes its own prompt" into a system that discovers strategies, remembers what survives, and acts on a bounded surface. Job `brain-evolution` (daily 3:00 AM ET) runs `runEvolutionCycle()`: **re-validate** every library strategy on the LATEST bars (decayed ones retire — this is the selection pressure), **discover** new configs for a deterministically rotating symbol slice (`rotateUniverse`, so coverage broadens without overfitting or unbounded spend), **resolve** cross-surface decision outcomes against real bars, then **prune**. Each stage is independently fault-tolerant.
- **Execution model (`utils/backtest.js`)** — fills are **next-bar** by default (a signal on bar i fills at bar i+1's open, else close; a final-bar signal never fills) and every trade pays **`costBps` round trip, half per side** (`costBpsForSymbol` reads the EV gate's `ROUND_TRIP_BPS`, so crypto backtests pay 60bps like crypto picks do). Buy-and-hold pays the same round trip so `alpha` compares like with like; an open position is liquidated net of cost in `finalValue`. `fill:'close'` keeps the legacy same-bar model for comparison. Metrics carry `costBps`/`fill`/`costPaid`. Tests: `tests/backtest-execution.test.js`.
- **Out-of-sample validation.** `strategy-lab.evaluateSignals` splits history into two DISJOINT windows (older 70% / newest 30%, signals computed on the full series so indicators are warm) and `consistentVerdict` requires `validated` in BOTH — the full-range backtest alone, with evolution keeping the best of many proposals, selected for luck. Composed rules now face the same bar (they needed only alpha>0 on one window). **Re-validation is forward-only** (`brain-evolution.forwardMetrics`): it scores only bars AFTER `discoveredAt` (≥`MIN_FORWARD_BARS` 20, ≥1 completed trade, else skipped as not-yet-evidence), because re-running "the latest 2y" re-tested ~99% of the admission window. In `strategy-library.js`, fitness confidence counts only `forward` validations, `buildStrategyBlock` injects only strategies with ≥1 forward pass, and "proven" in `libraryStats` means the same.
- `strategy-library.js` — persistent JSONL of backtest-validated strategies. `scoreValidation()` scores a run 0-100 from MEASURED engine metrics (alpha + Sharpe); `computeFitness()` weights recent validations higher and **discounts unproven strategies** (confidence saturates at 3 validations) so a single lucky backtest can't rank highly; 2 consecutive failures or `STALE_DAYS` without a pass ⇒ auto-retired. `getStrategyBlock()` injects proven survivors into the Brain prompt. The LLM only proposes; `utils/backtest.js` is the sole judge.
- `learning-store.js` — ONE append-only decision log every surface writes to (`SURFACES`: ai-brain, advisory, strategy-lab, paper-broker, copilot, trading-analysis) with per-surface AND cross-surface calibration. Direction-aware scoring (a `sell` wins when price falls). Rates are gated behind `MIN_SAMPLE` so noise never steers anything; `getCalibrationBlock()` returns '' until it has earned something to say. **Decider splits** `byPersona` / `byModel` / `byRegime` come from `meta` (`byMeta()`) — properties of the DECIDER rather than of the market, so a difference between two of them is the one thing on the record the system controls. `routes/recommendations.js` records every surviving pick with `meta.persona`, so "does Buffett actually beat Wood on this system" is now measured rather than stylistic; `routes/ai-brain.js` stamps `modelVersion`/`promptVersion`/`regime`. Rows missing a field are excluded, not pooled.
- `paper-broker.js` — **bounded write access**. Kill switch `PAPER_TRADING_ENABLED` must be exactly `'true'` (default off). Hard limits (position %, open positions, trades/day, min order) where env vars may only TIGHTEN, never loosen, past `CEILINGS`. Structural bans fall out of the arithmetic: no shorting (sell capped at shares held), no leverage (buy capped at cash). Rejected orders are written to the audit trail alongside fills. Job `paper-execute` (9:45 AM ET Mon–Fri) trades cached scan picks scoring ≥70.
- `strategy-dsl.js` — **widened search space**: the Brain composes NEW strategies instead of only tuning the 4 catalog types. The LLM emits a declarative JSON rule tree over a whitelist of ~23 feature primitives (`FEATURES`) + comparison/cross/boolean ops; `validateRule()` is an allow-list gate (unknown feature/op, type mismatch, wrong arity, >`MAX_NODES`/`MAX_DEPTH` ⇒ rejected before anything runs), then a deterministic interpreter emits +1/-1/0 signals for `simulateWithSignals()`. **No LLM-authored code is ever executed — no eval, no Function()**; exit wins entry/exit ties (risk-off). Stored as `strategy: 'composed_rule'`, `params.rule`, with a human-readable `description`. Cycle stage `discoverCompositions()`.
- Routes `routes/evolution.js` → `/api/evolution/status|strategies|paper|paper/trades`, admin-only `POST /run` and `/paper/reset`. Tests: `tests/strategy-library.test.js`, `tests/learning-store.test.js`, `tests/paper-broker.test.js`, `tests/brain-evolution.test.js`, `tests/strategy-dsl.test.js`.

## Exposure Map — supply chain / peers, evidenced (`lib/exposure-map.js` + `lib/edgar-search.js` + `lib/entity-graph.js` + `routes/exposure.js`)
Answers "which LISTED stocks have exposure to X, and which should I buy" for X = a public ticker OR a private company (SpaceX, OpenAI, Anduril…). For private anchors this is the only tradeable angle that exists.

**Why it is built this way.** Asked for "SpaceX's suppliers" any model produces a confident list that is partly invented, and the invented rows are indistinguishable from the real ones at the point of use. So this follows the repo's standing split — **the LLM proposes, deterministic code judges** — exactly as strategy-lab/strategy-dsl do:
1. **Candidates come from EDGAR, never from a model.** `edgar-search.findMentions()` runs EDGAR full-text search on the anchor's LEGAL ENTITY NAME (from `company_tickers.json`), because a bare ticker is a terrible search term — `dedupeAliases()` drops single generic words (`META`, `Intel`) that would match boilerplate everywhere. CIK hits map back to tickers via `filings.loadCikIndex()`; an unlisted filer is dropped as unactionable.
2. **The model only ever sees retrieved filing text.** `filings.extractTermWindows()` cuts ±600 chars around each mention of the anchor — deliberately NOT `extractSections()`, which anchors on Item 1A/MD&A and so skips Item 1 Business where named customers actually live. Its job is narrow: pick a relation and quote a sentence.
3. **`verifyFinding()` is the gate.** The quote must be present VERBATIM in the source window (whitespace/smart-quote normalisation only — never fuzzy) AND must itself mention the anchor, or the finding is **discarded**, not softened. A real sentence lifted from elsewhere in the filing fails too. This is `validateRule()`'s role in strategy-dsl: a boundary the model cannot argue past.
4. **`scoreEdge()` ranks from measured facts only** — relation weight × form weight (10-K/20-F > 8-K > 10-Q) × recency, plus corroborating filings and the disclosed revenue % when the filing states one. Never model confidence.

`RELATIONS`: supplier · customer · partner · holder · peer · competitor. `toUniverse()` **excludes competitors** — their exposure runs the other way, so including them would quietly add shorts to a long screen.

**Peers need no LLM and no network**: `findPeers()` reads industry classification from `lib/symbol-db.js`, so a run still returns something useful when EDGAR search is down (`searchAvailable()` probes it). **But a PRIVATE anchor has no peer fallback** — peers come from an industry classification only a listed company has — so when full-text search is unreachable a SpaceX/OpenAI map is genuinely empty; the response says so in `notes` + `searchAvailable:false` rather than letting an empty map read as "nothing is exposed".

**Fund holdings — the private-anchor path** (`edgar-search.js:fundHolders`, `routes/exposure.js:describeHolding`). You cannot buy SpaceX; you can buy a LISTED closed-end fund or BDC that holds it, and its NAV moves with the stake. `fundHolders()` full-text-searches `FUND_FORMS` (`NPORT-P` `N-PORT` `N-CSR` `N-CSRS` — the N-PORT family has appeared under both spellings) and **refuses a listed anchor**: every index fund holds NVDA, so that would rank the fund industry, not exposure. **No LLM is involved** — a schedule of investments already STATES the relationship, so `exposure-map.js:extractHoldingEvidence()` slices the quote straight out of the filing (verbatim by construction, not by verification) and reads the stated % of net assets only when a literal `%` sits in the same row. `verifyFinding()` still runs over the result — it cannot fail there, and that is the point: one definition of evidence, no path around it. All four fund-form spellings are in `FORM_WEIGHT`; at the default weight a holding scores 24 against a floor of 25 and the whole path disappears with no error (`tests/exposure-map.test.js` pins this).

**The diff is the alpha** (`entity-graph.diffEdges`, same shape as `signal-flips`): `added` / `dropped` / `materiality_up|down`. **`dropped` is the one worth reading** — a supplier that stops naming a customer in its concentration disclosure is reporting a lost relationship, typically a quarter before the revenue line does. Job `exposure-refresh` (weekly Sun 4:30 AM ET) rebuilds tracked anchors and logs the changes.

**Which ones to buy**: the map is a UNIVERSE GENERATOR, not advice. `POST /:anchor/research` hands the surviving tickers to `POST /api/ai-brain/analyze` (`symbols` takes precedence over `scanMode`), so all existing scoring/calibration applies unchanged. Store: `data/entity-graph.jsonl` (gitignored, append-only, latest snapshot per edge wins).

**NETWORK CAVEAT**: `efts.sec.gov` (full-text search) is a different host from the `www.sec.gov`/`data.sec.gov` endpoints `lib/filings.js` already uses, and was NOT reachable from the sandbox this was written in — every network function takes an injectable `fetchImpl`, parsing is tolerant of field renames, and failures degrade to the peer path. **Verify against the live endpoint before relying on the supplier path.**

`lib/filings.js` gained: `ALL_FORMS`/`FOREIGN_FORMS` (**20-F/6-K — TSM, ASML and most ADRs never file a 10-K, so a 10-K-only lookup returned nothing for them**), `loadCikIndex()` (CIK→ticker/legal-name), `getCompanyMeta()` (SIC + `foreignIssuer`), `extractTermWindows()`. UI: `src/components/Exposure/ExposureView.jsx` (route `exposure`) shows the verbatim quote + filing link on every card — the evidence is the product. Tests: `tests/exposure-map.test.js`, `tests/edgar-search.test.js`, `tests/entity-graph.test.js`, `tests/filings-exposure.test.js`, `tests/exposure-route.test.js`.

## Source independence — syndication is not consensus (`lib/source-independence.js`)
Every provider in `routes/sentiment.js` averaged per-article sentiment and reported `headline_count` as articles seen. A wire story republished by five outlets is ONE story wearing five outfits: five identical scores in the mean, five times the claimed corroboration. When the sixth article is an independent piece pointing the other way, one press release outvotes it 5:1 — and that number reaches the AI Brain prompt, its picks reach `brain-learnings`, and calibration measures confidence nobody had.

`clusterArticles()` unions derivative copies on four signals — canonical URL (tracking params stripped), wire-service fingerprint (PR Newswire/Business Wire/… + a token fingerprint of the text after the marker), near-duplicate headline, near-duplicate body — and **a cluster sums to exactly 1.0** (`1/n` per member), so `independentCount` is a true count of distinct stories. `weightedSentiment()` returns both `mean` and `rawMean` so the correction is visible, never silent. Responses now carry `headline_count` (raw), `independentCount` (stories) and `syndicated`.

**Applied in three places**: `routes/sentiment.js` (all five providers), `lib/social-sentiment.js:fetchGoogleNews` — the lane the **AI Brain** scan reads, and the worst offender, since one wire story surfaces under a dozen outlet names and `classifyTitle` scored each independently (`total` is now distinct stories, `rawTotal` articles seen, `syndicated` when they differ) — and `routes/research-notes.js:/auto-research` (**Second Brain**), which de-duplicates Finnhub headlines BEFORE its 10-item slice so the budget buys ten stories.

**The polarity guard is the load-bearing safety rule**: "Apple Q3 earnings beat" and "…miss" share four of five content tokens, so a naive similarity rule merges them and silently deletes half of a real disagreement. Articles whose sentiment points opposite ways are **never** unioned, however identical the text — even on a byte-identical URL. Two related traps are pinned by tests: selecting cluster representatives on `weight===1` drops a syndicated story *entirely* (no member of a 4-cluster has weight 1), and dropping single-character tokens merges "guidance to $5" with "to $9". The Claude-scored lane de-duplicates BEFORE its 5-headline budget is spent, so it buys five stories not five copies. Pure, tested (`tests/source-independence.test.js`, `tests/sentiment-independence.test.js`).

## Citation gate — Advisory sources must be supported (`lib/claim-support.js`)
The Advisory prompt asks each pick to cite the SPECIFIC injected data and to "NEVER invent figures"; server-side only the SHAPE was enforced (non-empty strings, ≤4). `verifyCitation(citation, evidence)` is the mechanical tier — no model call: does the figure or phrasing actually occur in the block we injected? `routes/recommendations.js` builds `evidenceBlock` from the exact snippets interpolated into the prompt, audits every pick, **drops** unsupported citations (they render to the user as evidence, and evidence that failed its own check is worse than none), keeps the pick, and reports `citationCheck` per pick + `citationAudit` on the response — same contract as `edgeGate.rejected`.

Three rules, each pinned: **rounding is not fabrication** (a cited number matches when an evidence number rounds to it *at the precision it was written to* — `$209.87` supports `$210`, not `$212`; a 1% tolerance would wave `$212` through); **numbers OR wording, never both** (a citation stating a verified figure passes on that alone, because "fwdP/E 31.2 below peers" is interpretation, and a gate that cries wolf gets ignored — a figure-free citation must have its wording grounded); **the gate stays inert with no evidence** (`unverifiable`, not reject — firing hardest when it knows least destroys the feature). Form names/quarters/fiscal years (`10-K`, `Q3`, `FY26`) are names, not quantities. `RecCard` renders surviving citations with a check and says when something was removed. Tests: `tests/claim-support.test.js`, `tests/recommendations-citation-audit.test.js`.

## Symbol search — every provider, then rank (`lib/symbol-search.js`)
`GET /api/search` was a **first-non-empty-wins cascade**: one Finnhub row silenced FMP, TwelveData, AlphaVantage *and* the free 300k-symbol local index. That is why whole classes of instrument were unsearchable — mutual funds especially, since FMP is the only provider this repo trusts for NAV (`KNOWN_MUTUAL_FUNDS → FMP only`) and it was reached only when Finnhub returned literally zero rows. Second defect: every provider sliced its own list (Finnhub 10, FMP `limit=10`, TD 8, AV 8) **before** ranking ran, so an exact ticker match at position 11 was gone before anything could promote it.

`mergeQuotes(lists, q, {limit})` merges, dedupes by symbol and ranks, and **the slice happens last**. `scoreQuote` orders exact symbol > symbol prefix > name word-boundary > symbol infix > name infix — a word-boundary name hit ("Apple Inc" for APPLE) beats a symbol that merely contains the letters (XAPPLEY), which is almost never wanted; the query is regex-escaped since it is arbitrary input. Ties break on **corroboration** (two providers returning a symbol beats one), then symbol length. `foldQuote` merges fields across providers — a blank never overwrites a value, so a sparse Finnhub row picks up FMP's exchange; `PROVIDER_RANK` decides a field both filled. Each result carries `sources`.

Route side: **tier 1** runs Finnhub + FMP in parallel plus the local index (no network, no quota); **tier 2** pays for TwelveData + AV only when tier 1 found nothing, so the common case stays cheap. A total provider outage still answers from the local index rather than returning `[]`, which reads as "no such stock". `SEARCH_PROVIDER_CAP` (25) replaces the per-provider slices; `?limit=` is honoured up to `MAX_LIMIT` (50). `fromSymbolDb` maps crypto to `CRYPTO` — the old inline fallback called it `EQUITY`. **Note `SYMBOL_DB_COUNTRIES` defaults to `United States`**, so non-US equities are absent from the local index until it is set (`ALL` disables the filter). Pure parts tested (`tests/symbol-search.test.js`).

## Fundamental Screener — yield quality, not raw yield (`lib/fundamental-screen.js`)
Every discovery surface in this repo ran over a hardcoded ~20-symbol list — `routes/dividend.js:DEFAULT_UNIVERSE`, and *every* `SCAN_UNIVERSES` entry — while `lib/symbol-db.js` sat on 300k+ classified symbols nobody was searching.

**Sorting by dividend yield ranks the market's worst businesses first.** Yield is dividend / price, so it rises when the price falls; the highest yields on any screen are overwhelmingly companies the market expects to CUT. So `yieldReward()` rewards yield to `YIELD_SATURATION` (6%), plateaus to `HIGH_YIELD_WARN` (8%), then **decays to zero** at `YIELD_ABSURD` (20%) — and the whole thing is multiplied by `sustainability()` (payout ratio, FCF coverage, leverage). An uncovered 12% yield scores **27**; a covered 3% yield scores **75**. The same 12% yield when actually funded outranks both — coverage is what separates them, not size. Pinned by tests, including that the inversion holds on the yield pillar ALONE and isn't smuggled in via profitability.

Load-bearing details: a **negative payout ratio is the worst case, not a safe-looking small number** (it means the dividend is paid with no earnings behind it — treating -20 as "below the ideal max" would score it as the safest dividend on the screen); negative margins floor at 0 rather than contributing negatively, so one bad metric can't cancel genuine strength elsewhere; `fcfPayoutRatio` is **derived** from per-share FCF and dividend, because "can it fund this" is exactly what the earnings payout ratio misses when earnings and cash flow diverge.

**An absent input is not a zero** — scoring an unknown company as 0 ranks it below a measurably bad one, a claim the data doesn't support. Each pillar scores only what is present, reports `coverage`, and anything under `MIN_COVERAGE` (0.5) returns `verdict: 'insufficient-data'` and is **excluded** from the ranking rather than ranked low (same stance as `recomputeComposite` returning null on partial input). A no-dividend growth stock legitimately scores 0 on the yield pillar and ranks on profitability alone (`pillars: 1`).

**Units are percent-valued throughout** (3.2 means 3.2%, never 0.032), with `looksLikeFraction()` as the guard — deliberate pedantry, since `lib/price-coherence.js` exists because a percentage reached a price field and nothing noticed.

**The LLM explains a ranking it did not produce.** `explainRanking()` is handed the finished order and told not to reorder, add, remove or state any figure not shown; an explanation for a symbol outside the ranking is **discarded** server-side, and a failed explain call never costs the ranking (`explanation: null`, noted). Tests: `tests/fundamental-screen.test.js`, `tests/screener-route.test.js`.

## Price coherence gate — the levels must follow from the percentages (`lib/price-coherence.js`)
The AI Brain prompt asks for percentages (`targetReturn`, `stopLoss`) **and, separately, for six absolute dollar bounds** (entry/target/stop zones). Nothing checked the two against each other. A real scan card shipped: entry $29.67–$30.87, **target $24.50–$26.00**, stop $27.09–$27.91, labelled `+−15%` / `−27.5%` on a "Moderate Buy". Rebuilding "±1.5% around stop" from the **number 27.5** reproduces $27.09–$27.91 exactly — the model had used the stop-loss PERCENTAGE as a dollar PRICE (a genuine 27.5% stop there is $21.95). The target disagreed with its own stated return by 1.9%, sat *below* the stop, and `compositeScore` was not the weighted average the prompt defines it to be (22 vs 26.15).

Every one of those numbers is derivable from inputs already held, so `coherentZones()` derives them rather than trusting them — same division of labour as `validateRule`/`verifyFinding`/the EV gate. The entry is the one level the model keeps an opinion about (it may want a pullback fill), overridden only past `ANCHOR_TOLERANCE` (3%) from the live quote; target and stop zones are **always** recomputed from that anchor, at the prompt's own ±2%/±3%/±1.5% half-widths, and `compositeScore` is recomputed from its five components (the claimed value kept as `compositeScoreClaimed`). `looksLikePercentAsPrice()` reports the unit confusion rather than silently patching it — it says the model misread the schema. **Correction from a live scan (prompt v4):** the confusion runs the other way — the model writes the stop PRICE into `stopLoss` (15 of 20 picks: BTC 74000, NVDA 210, ARKK 82 on an $89 stock). Values ≥100 were dropped and values <100 were read as percents, shipping an 82% stop at $16. `valueUnit()` now decides from the evidence: a value on the right side of the entry that its own zone is centred on, or a stop ≥100 below entry, is a PRICE and is converted to a percent (`stopLossPrice`/`targetPrice` keep the original, reported in `repairs`). The prompt now states the units, and `SCAN_PROMPT_VERSION` is 4.

**Two things are deliberately NOT repaired**, because code cannot know which side of the contradiction was meant: a **buy** whose `targetReturn` ≤ 0 (is the target wrong, or the verdict?) and a `stopLoss` outside (0,100). Those picks are **DROPPED** and reported — same contract as `edgeGate.rejected` and `citationAudit`. Surfaced as `coherenceAudit` on the scan response.

**The verdict decides whether that rule applies.** The scan schema used to offer only buy verdicts, so a model that disliked a symbol had exactly one way to say so — a negative `targetReturn` on a "Buy" — the gate dropped the row, and a **single-symbol scan went to zero picks and 500'd** ("no internally consistent picks — try again"). Fixed at the root: `agentVerdict` gained **`Avoid`** plus a prompt rule saying not to encode bearishness as a negative target, and `isLongVerdict()` derives `long` from the verdict (`ABSTAIN_VERDICTS`: avoid/no trade/hold/neutral/sell/strong sell) so a pick that declines to recommend is **passed through as `actionable: false`** with no derived zones — there is no trade to price. A missing verdict still defaults to long, so the gate never weakens by omission. Abstains are excluded from `logPrediction` and `recordDecisions` (resolving one against bars would score a trade nobody was told to take) and are exempt from the auto-threshold filter (they explain the slate). The CARD must say so too: `VERDICT_CONFIG` gained an `Avoid` entry (without one it fell back to `'Buy'` and rendered "Avoid" in **mint** — a decline styled as a go), the target/stop chips are replaced by a "No trade — declined" marker (`signedPct(0)`/`drawdownPct(0)` rendered `0%` / `-0%`, which reads as a flat trade rather than no trade), `PriceZones` renders an explicit "No entry, target or stop" panel instead of returning null (silent absence reads as a missing feature), and the rank badge is suppressed ("#1 Avoid" reads as the top recommendation). **An empty slate is now a 200 with `abstained: true` + `coherenceAudit`, never a 500** — same stance as the EV gate's `abstained`; the UI names the symbol and the reason instead of inviting a re-roll of a paid call. `SCAN_PROMPT_VERSION` bumped to **2**. Tests: `tests/ai-brain-abstain.test.js`.

**It runs before `logPrediction` and `recordDecisions`**, which is the point: those stores ran over ALL picks pre-filter, so an incoherent pick was resolved against real bars weeks later and counted as measured evidence, corrupting the calibration the Brain steers by.

Advisory had the same hole from the other side: `routes/recommendations.js` rebuilt `takeProfitPrice`/`stopLossPrice` **only when the live quote moved the entry ≥3%**, so inside that band the model's own levels survived with nothing checking them (`validateRecommendations` never looked at them either). They are now recomputed unconditionally. `src/utils/formatPct.js` takes the sign from the value instead of hard-coding `+`, so a stale cached scan can never render `+−15%` again. Pure, tested (`tests/price-coherence.test.js`, `tests/recommendations-price-coherence.test.js`).

## Untrusted content — fetched text is data, never instructions (`lib/untrusted.js`)
`copilot.js:read_url` fetches whatever page the user names, `lib/filings.js` pulls SEC narrative, `earnings-call.js` pulls transcripts, and `exposure-map.js` hands filing windows to a model whose whole job is deciding what the text establishes. Any of those can carry a sentence addressed to the model. `wrapUntrusted(body, source, {maxChars, label})` fences it with a data-not-instructions preamble, and three things are enforced *inside* the helper so no call site can get them wrong: forged fence tags are **neutralised** (opening or closing, any case, whitespace inside the tag — renamed, left visible for forensics), the `url` attribute is HTML-escaped with control chars stripped, and **truncation happens inside the wrapper** so a caller slicing to a char budget can never sever the closing fence. `UNTRUSTED_POLICY` is pasted into every prompt that receives fenced content — a fence the model was never told about is decoration. Pure, tested (`tests/untrusted.test.js`).

**Second Brain `/scout`** (`routes/research-notes.js`) fetches a user-supplied URL and had its own hand-rolled `<external_page_content>` fence. Right instinct, **forgeable delimiter**: a page containing its own closing tag ended the fence early and everything after it read as prompt, and the URL was interpolated into the preamble raw. It now uses `wrapUntrusted`, which neutralises the tag and carries the URL in an escaped attribute (`tests/brain-surfaces-hardening.test.js`).

## Expected-value gate — the ability to abstain (`lib/expected-value.js`)
The Advisory prompt asks the model for a FIXED slate (20–22 picks), so it always returns a full one whether or not that many ideas are worth acting on. This module supplies the missing judgement deterministically in code — same division of labour as the rest of the repo (the LLM proposes, measured math judges), and the model is never told a gate exists so it can't pad toward it.

`evaluateTrade({winProb, targetReturn, stopLoss, assetType, minNetEdge})` scores one pick net of a **per-asset-class round-trip cost** (`ROUND_TRIP_BPS`: stock 10bps, etf 8, fund 10, **crypto 60** — crypto pays real taker fees on both sides plus a wider spread; unknown → 20). Returns `netEdge`, `breakEvenWinProb` (the hit rate this payoff structure requires — converts "looks good" into a testable claim), `winProbMargin` (measured rate minus break-even), and a `verdict` of `act` / `thin` / `reject`.

Built on the identity **p(W−c) − q(L+c) ≡ pW − qL − c**: charging the cost to the payoffs and subtracting it from the gross edge give the same number, so the EV that produced the verdict and the Kelly size derived from `netWinFrac`/`netLossFrac` can never disagree. `routes/recommendations.js` filters on `actionable`, reports every rejection in `edgeGate.rejected` with a reason, and sets `abstained: true` when nothing clears — an empty slate is a real answer, surfaced in the UI by `EdgeGateBanner` in `BuySignalsView.jsx` (never as "no picks match your filters"). Floor is `MIN_NET_EDGE` (50bps), overridable via `ADVISORY_MIN_NET_EDGE`. On a cold start `winProb` falls back to a conservative 0.5, which leaves the gate inert rather than arbitrary. Pure, tested (`tests/expected-value.test.js`, `tests/recommendations-edge-gate.test.js`).

## Kelly position sizing (`lib/kelly.js`)
Advisory position sizing (suggests, never executes). `fullKelly(p,W,L)` = asymmetric-payoff Kelly `(pW−qL)/(WL)` clamped ≥0; `suggestedSize({winProb,winFrac,lossFrac,fraction=0.5,maxFraction=0.2})` applies fractional Kelly + a hard cap (full Kelly can exceed 100% leverage under a tight stop). Win-probability comes from EMPIRICAL calibration via `winProbFromStats(computeStats(...))` — the resolved-pick win rate — NOT a raw confidence score. Specificity order, most specific first: **asset class** (`byAssetType`; stocks/ETFs/crypto have genuinely different hit rates and a blended number sizes all three wrong) → per-confidence bucket → overall (30d, then 7d) → conservative default. Every level is gated on `minN` so a thin segment falls through instead of sizing off noise; `source` reports which level was used. Wired into `routes/recommendations.js`: each pick gets a `sizing` field (suggestedPct/fullKellyPct/edgePerUnit/winProbSource) from its targetReturn/stopLoss. Pure, tested (`tests/kelly.test.js`).

## Recommendation journal (`lib/rec-journal.js`)
"Decisions as commits" — each Advisory run is appended to `data/rec-journal.jsonl` (gitignored) as a content-hashed, versioned entry (8-char `id`, timestamp, rationale = market outlook, normalized picks, persona/params). `hashEntry`/`buildEntry`/`diffEntries` are pure; `diffEntries(prev,next)` reports added/removed/changed picks by symbol. `routes/recommendations.js` appends on each generation (best-effort) and exposes `GET /api/recommendations/journal` (requireAuth) → user's history newest-first, each entry annotated with a `diff` vs the previous run. Advisory/audit only, no execution. Pure parts tested (`tests/rec-journal.test.js`).

## Prompt token compaction (`lib/compress.js`)
`compactProse(text)` strips non-informative structure (whitespace runs, separator/page-number lines, repeated lines, ToC/boilerplate) from prose-heavy context BEFORE it's sliced into a prompt — fewer tokens, same meaning, so the same char budget carries more signal. NEVER alters numbers/tickers/currency/% (financial precision preserved). `compactWhitespace(text)` is the whitespace-only, line-preserving variant. Pure, tested (`tests/compress.test.js`). Applied at the heavy injection points: SEC filing narrative (`lib/filings.js` → before `extractSections`) and earnings-call transcript (`routes/earnings-call.js` → before the 6k slice). Typical ~30-50% shrink on filing/transcript boilerplate.

## Internal loopback auth (`lib/internal-secret.js`)
Server-to-server calls (scheduled jobs, route-to-route proxying via `/api/...` over `127.0.0.1`) bypass `requireAuth` only when BOTH the socket is loopback AND a per-process secret (`isInternalRequest()`, regenerated fresh on every boot — never persisted, never leaves the process) is sent as `x-internal-secret`. Defense-in-depth over the old loopback-IP-only check: a forged header alone can never grant access, even if the deployment topology ever changed such that `req.socket.remoteAddress` could appear loopback for external traffic. All internal callers (`routes/alerts.js`, `routes/copilot.js`'s `dispatchTool`, `routes/market-focus.js`, `routes/options-flow.js`, `lib/backtest-queue.js`, `lib/scheduled-jobs.js`) send it alongside the legacy `x-internal: '1'` marker.

## Groq fallback model (`lib/ai-router.js:GROQ_MODEL`)
One constant, `process.env.GROQ_MODEL || 'openai/gpt-oss-120b'`, imported by every Groq call site (`ai-brain` ensemble + labels, `recommendations` labels, `copilot` `PROVIDER_DEFAULTS`, `agent`, `ai-audit` pricing). Groq **decommissioned `llama-3.3-70b-versatile` on 2026-09-21** — it now 404s with "model does not exist" — and the ID had been hard-coded in seven places. That is not merely a degraded fallback: while `CLAUDE_PAUSE_UNTIL` is active Groq is the **only** provider, so a dead ID is a total outage, and the ai-brain ensemble second opinion fails silently (`ensembleConfirmed` just stops being logged). Keep it as one constant so the next decommission is one edit, overridable by env with no redeploy.

## Pausing Claude (`lib/ai-pause.js`)
Set `CLAUDE_PAUSE_UNTIL` to an ISO date (e.g. `2026-07-01`) to stop all Anthropic/Claude usage until that date — e.g. to preserve quota until a limit resets. While paused, `claudePaused()` is true: `lib/ai-router.js` routes its features to Groq (works only if `GROQ_API_KEY` set), the copilot's default Claude provider is transparently served by Groq, and direct Claude callers (`quantmind` `rebalancer` `sentiment` `agent` `research-notes` `brain-learnings` nightly) skip the call and 503/no-op. Auto-resumes after the date — no redeploy. Unset/blank/invalid → never paused.
